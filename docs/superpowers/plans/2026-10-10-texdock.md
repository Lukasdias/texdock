# texdock Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a dockerized, self-hosted, single-user LaTeX editor with project/file management, live PDF preview, SyncTeX navigation, and PDF export.

**Architecture:** Two docker-compose services — `db` (postgres:17-alpine) and `app` (one image: FastAPI + uv + Debian TeX Live, also serving the built React SPA). Postgres is the single source of truth for projects, files, and compile artifacts. Compiles run `latexmk` in a temp dir via a per-project asyncio queue, and results reach the browser over WebSocket.

**Tech Stack:** Python 3.13 + FastAPI + uv + SQLAlchemy 2 (async, asyncpg) + Postgres 17; React 19 + Vite 8 + TanStack Router/Query + CodeMirror 6 + Tailwind 4 + shadcn/ui + Motion + Sonner + React Compiler + pdfjs-dist; latexmk + TeX Live (Debian packages).

**Spec:** `docs/superpowers/specs/2026-10-10-texdock-design.md`

## Global Constraints

- Publish port as `127.0.0.1:8000:8000` (loopback only).
- Postgres is the only stateful store; the only named volume is `pgdata`. No file volume.
- Retain the 10 most recent compilations per project; prune older rows on insert.
- Upload cap 50 MB per file (`max_upload_bytes = 50 * 1024 * 1024`).
- Reject any path whose normalized form is absolute, empty, or contains a `..` segment.
- Compile timeout 120 s; on breach kill the whole process group.
- latexmk invocation: `latexmk -<engine> -synctex=1 -interaction=nonstopmode -halt-on-error <main_file>`.
- Engines: `pdflatex` (default) | `xelatex` | `lualatex`.
- No authentication in v1.
- TeX Live via Debian packages: `texlive-latex-base texlive-latex-recommended texlive-latex-extra texlive-fonts-recommended texlive-bibtex-extra latexmk`.
- Frontend: Vite 8, Tailwind 4 (via `@tailwindcss/vite`, no `tailwind.config.ts`), React Compiler enabled, TanStack Router (file-based), TanStack Query, CodeMirror 6, shadcn/ui, Motion, Sonner, pdfjs-dist.
- Backend dependencies managed with uv; Python 3.13.

## Review Focus

Inputs/conditions the spec implies but no feature step naturally covers. Each has a test pinned in the owning task.

1. **Path traversal** — `{path...}` values and upload filenames like `../x`, `a/../../b`, `/etc/passwd`, `%2e%2e/`. Must 400 and never touch outside the project dir. (T3, T5)
2. **Binary content on the text route** — a non-UTF-8 body `PUT` to a text file path. Must reject (422) or route to binary storage; never corrupt or 500. (T5)
3. **Runaway compile** — a document that never terminates or forks. Timeout must kill the whole process group; no orphan `latexmk`/`pdflatex`. (T7)
4. **Awkward filenames** — spaces, unicode, `#`, `%`, backslashes. Tree display, save, upload, and materialize+compile must all survive. (T5, T7)
5. **Artifacts before/after failure** — `GET .../pdf` with no successful compile must return 404 with a clear empty state; after a failing compile the last good PDF stays served. (T9)
